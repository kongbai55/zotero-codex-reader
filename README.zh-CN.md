# Codex Reader · Zotero 论文侧栏

在 Zotero 的 PDF 阅读器右侧与本机 Codex 对话。直接使用你平时 Codex App/CLI 的登录、模型、配置和服务；无需输入 API Key，无额外 HTTP 服务，无 npm 运行依赖。

## 安装

1. 先确认终端中的 Codex 可以正常使用，并已完成登录。
2. 在 Zotero 打开「工具 → 插件/附加组件」，点击齿轮，选择「从文件安装插件」。
3. 选择 `dist/zotero-codex-reader-0.6.0.xpi`。
4. 打开一篇 PDF，点击右侧绿色代码图标，Codex 会完整覆盖右侧内容区。
5. 点击右上角「⋯」打开连接设置，再点击「连接 Codex」。优先寻找桌面端自带的 Codex，再寻找单独安装的 CLI。

已在本机 Zotero **10.0.6 / Windows x64** 和 Codex CLI **0.163.0** 进行集成检查。使用的是 Zotero 7 起提供的侧栏接口；其他版本、系统尚未实测。

没有自动更新服务器。需要更新时，重新构建并手动安装 XPI。此版 Zotero 强制要求 HTTPS `update_url`，所以填入的是回环占位地址 `https://127.0.0.1:9/codex-reader-no-updates.json`，启动时仅关闭本插件的后台更新。手动检查更新会失败，不连接开发者站点，也无需运行更新服务。

## 0.6.0 拖放与粘贴附件

- 将文件或图片拖入 Codex 面板，或在问题输入框粘贴截图/复制的文件；也可点击输入框左下角「＋」多选文件。普通文字粘贴保持原有行为。
- 待发附件显示名称、大小和图片缩略图，可单独移除。支持只发送附件；发送失败保留附件供重试，切换论文后返回仍保留草稿（本次 Zotero 运行期间）。
- PNG、JPEG、GIF、WebP 按实际内容识别，作为图片输入发送给模型。TXT、Markdown、CSV、代码等文本在本地解码并附上内容，总计最多 60,000 字符，超出部分显示提示并保留完整文件引用。SVG/HTML 按文本处理，不执行其中的脚本。
- PDF、Office 文档和其他格式以本地文件副本提供给 Codex，由其只读工具读取；可解析的格式取决于本机工具环境，不能读取时应明确说明，不假装已读。
- 每条消息最多 10 个附件、单个最多 20 MB、合计最多 50 MB。添加时只在本地准备，点击发送后才交给 Codex。副本保存在 Zotero 配置目录的 `codex-reader-workspace/attachments/`，不加入 Zotero 文献库；移除未发附件会删除副本，已尝试发送的副本保留以供会话继续读取。关闭 Zotero 不会自动删除这些副本。

## 0.5.0 文件监听、反向登记与项目对话

- 不再固定每 5 秒轮询。文件变化通知触发刷新，短暂合并连续事件；打开列表和返回 Zotero 时补充检查。监听使用本机已有 Node（桌面捆绑或已安装），只在阅读器视图存在时运行，视图关闭后退出。找不到运行环境时显示提示，改用打开列表时刷新，不恢复固定轮询。
- 新建/添加项目使用官方目录深链接打开 Codex，由桌面端登记目录和处理必要的目录授权，不发送聊天。只有在桌面登记文件中实际出现后才视为同步成功；未确认的条目标为「等待 Codex 接收」。
- 旧版从聊天历史推断出的临时目录归档，不再混入正常项目列表；重复项目按真实身份合并，先前验证留下的测试项从插件列表排除。
- 选择项目后自动加载该项目的本地 Codex 对话；点击继续原会话，保留既有上下文，不再默认新建分支。
- 新建项目会话会附上最多 4 条近期本地项目对话的部分背景，总量不超过 16,000 字符，并明确标记为背景证据。继续原会话则直接沿用其历史，不重复插入。
- AGENTS.md 是项目指导，不是全部历史记忆。ChatGPT 镜像指导保持只读；纯云端 ChatGPT 聊天和账户长期记忆不由此本地 CLI 接口导入，请在桌面端查看。

## 0.4.1 自动同步 Codex 项目

项目列表启动即同步，每 5 秒自动刷新。Codex 中的新增、改名、目录变更和移除会反映到插件，无需手动导入历史。

## 0.4.0 注释、格式化回答、推理强度与项目

- 模型旁可切换推理强度，档位取自本机模型目录；换模型时自动去除不支持的档位。
- 回答支持 Markdown 标题、加粗、列表、表格、代码块，以及行内/块级 LaTeX 公式。复制保留 Markdown 原文。Marked 17.0.5 与 KaTeX 0.16.22 按 MIT 许可证随包提供，显示时不加载远程资源。
- **Enter 发送，Shift+Enter 换行**；中文输入法确认选词不会发送。
- 在 PDF 或回答中选中文字，点击「添加到对话」。多条选文会累积成编号注释，可添加评论、编辑和单独移除；回答选文带高亮及编号。点击输入框里的注释卡片可重新编辑。请求成功提交后清空待发注释，已发送内容保留在消息中。
- 会话列表中可以删除某一条历史或当前会话。确认后调用 `thread/delete`，永久删除该会话及其子会话；不支持的 Codex 版本会报错并保留本地显示。
- 在会话抽屉的「项目与记忆」中创建项目文件夹、添加已有文件夹，并自动跟随 Codex 保存的本地项目。为论文选定项目后，新建和分支会话使用该目录。
- 项目记忆使用项目文件夹中的 **AGENTS.md**，手动保存后可供两边的新会话读取。编辑器会载入整个原文件，并检测载入后的外部修改。保存后，该项目在插件中的对话会开始新会话，旧 Codex 历史仍保留。

**当前项目同步：** Codex → 插件在登记文件变化时更新。插件 → Codex 使用官方目录深链接，由桌面端接收后自动确认。插件不改写桌面私有设置、不读取凭证。参见[官方深链接说明](https://learn.chatgpt.com/docs/reference/commands#deep-links)。

## 0.3.0 独立阅读面板

点击绿色代码图标后，Codex 覆盖整个右侧内容区，包括原有文献标题及模块；仅聊天记录和面板内的列表可以滚动。面板按实际可用宽度定位，不会延伸到右侧图标栏下面。点击其他模块图标，或右上角「×」，即可恢复文献信息。切换论文时保留各自的对话与草稿。

## 聊天界面

采用 Codex 桌面端风格：可收起的会话列表、简洁消息区、固定在消息区下方的圆角输入框、模型选择和发送/停止按钮。宽栏并排显示历史与聊天，窄栏用抽屉展开历史；跟随系统深浅色外观。

注释数量或「＋ 添加上下文」打开预览和提取面板；右上角「⋯」包含连接设置、复制对话和存为笔记。此界面由插件独立实现，并非嵌入 Codex App。

## 阅读和提问

- 在 PDF 中选中文字，点击弹出菜单里的「添加到对话」。这一步只在本地填入上下文，不发起请求。
- 点击输入框下方注释数量或「＋ 添加上下文」，可检查、删改内容。
- 也可以点击「提取前 20 页文本」，使用 Zotero 本地 PDF 提取器。上限为 60,000 字符，截断时会提示；这种提取方式不包含图像，可另外粘贴截图或添加图片交给支持图片的模型。
- 输入问题，点击「发送」或按 **Enter**（**Shift+Enter** 换行），可实时查看逐步返回的回答。
- 「总结」「解释」「翻译」只填入问题草稿，不会自动发送。
- 每篇 PDF 分开维护会话；「停止」中断当前生成。「新会话」创建新的上下文，不删除 Codex 已保存的历史。
- 点击「复制对话」复制纯文本；「存为笔记」才会写入 Zotero 文献库。如果 Zotero 开启了同步，该笔记会按你的同步配置上传。

发送的数据包括：问题、当前论文标题、上下文框里的文字、手动添加的附件及其本地副本路径，以及 Codex 会话此前的上下文。新建项目会话还会带入前述有限的近期项目背景。未点击提取/加入选文/添加附件时，不会自动读取正文。插件没有自动扫描整库的功能。

## 与 Codex App 的互通范围

**可以复用：**

- 同一 `CODEX_HOME`（未设置时为 Codex 的默认目录）中的登录与配置。
- CLI app-server 能加载的模型、MCP、技能及插件服务。插件不会复制或重写你的 Codex 配置。
- 从 `thread/list` 读取的历史会话。点击左上角会话列表按钮，再点「加载 Codex 历史」并点击某条会话，继续原会话并沿用其历史。
- 账户用量接口返回的限额信息。

**不能等同于完全同步 App：**

- 本插件启动一个独立的 `codex app-server` 进程，不连接 App 正在运行的会话进程。
- 继续原会话会向同一线程追加消息；桌面界面可能需要刷新，不能同时写入正在运行的会话。
- App 特有的界面工具、临时注入的连接器、浏览器宿主、审批窗口等不一定对独立 app-server 开放。可用范围由本机 Codex 决定。
- 共用会话存储不保证新对话立即出现在 App 当前的侧栏筛选中，也不保证 App 的进行中状态可读。
- 复用的是 Codex 的全局配置；不会自动进入 App 当前项目；可手动选择同一个项目文件夹，加载其配置及 AGENTS.md。
- 历史列表最多显示最近 40 条。单条删除需要本机 Codex 支持 `thread/delete`。

若 Zotero 和 App 使用不同的账户、系统用户或 `CODEX_HOME`，它们不会自动共享。配置模型列表为空或历史读取失败时，会保留错误信息供排查，而不会转向其他服务。

## 凭证与聊天隐私

这份代码采用小型独立实现，没有复制参考插件的运行时代码。它没有广告、遥测、开发者服务器、远程脚本或自动更新下载；Markdown 和公式由随包提供的 Marked 与 KaTeX 处理。

- 插件通过 Mozilla 的 **Subprocess** 直接启动已安装的 Codex 原生可执行文件，使用 **stdin/stdout JSON 消息**通信，不开监听端口、不经过命令行 shell。
- 插件不读取、不复制、不展示 `auth.json`、API Key 或 OAuth token。认证由 Codex 自己处理。需要登录时，只有点击「官方登录」才会打开官方登录页面。
- 插件会记住可执行文件路径、项目目录及论文与项目的关联；只有点击保存共享记忆才写入所选项目的 AGENTS.md；插件聊天显示和草稿留在 Zotero 进程内存中，关闭 Zotero 后不恢复。
- **Codex 本身的历史保存、模型提供商、网络请求、日志、遥测、MCP、插件及 hooks 按你现有配置运行。** 因此不能声称聊天只在本机，也不能声称现有配置中的其他服务不会接触内容。该行为是复用你现有配置的结果。
- 论文文字和模型输出始终作为不可信文本处理；Markdown 通过限定的 DOM 元素显示，原始 HTML 作为文本处理，危险链接协议被拒绝；公式使用关闭信任及限制展开次数的 KaTeX，不加载回答里的远程图片。
- 新建/分支会话使用只读沙箱及按需审批，不修改你的全局设置。已有 Codex 服务仍可用；需要客户端审批的命令、文件操作和服务交互会显示确认。
- 论文内容与问题会发送给当前 Codex 配置中的模型。不要把「本机 CLI」误解为「本地运行模型」。
- 与所有 Zotero 桌面插件一样，本插件本身具有较高本地权限；你可以审阅 `addon/` 中的全部源码。安装包仅包含这些文件。

本项目没有对 `llm-for-zotero` 做完整安全审计，用户的隐私顾虑不等于原插件存在泄露行为。它是功能参考：https://github.com/yilewang/llm-for-zotero 。

## 找不到 Codex 时

在侧栏右上角「⋯ → 连接设置」中填写 Codex 的完整路径并保存。Windows npm 安装可填写：

```text
C:\Users\你的用户名\AppData\Roaming\npm\codex.cmd
```

插件会定位其包内的 `codex.exe`，不会执行 `.cmd` 或 `.ps1`。对于其他安装方式，直接填写真正的原生可执行文件路径。

若提示未登录，先确认普通终端中的 `codex login` 已成功，或点击侧栏「官方登录」。不要求再次登录已经被 Codex 正确识别的账户。

点击「重新连接」会断开所有此插件会话的运行时连接，内存中的聊天显示会清空；已由 Codex 保存的历史仍可通过历史列表找到。生成期间会禁止重连。

## 构建与检查

需要 Node.js（运行测试）和 Python 3（打包），构建过程不下载依赖。

```powershell
node --test tests/core.test.cjs
python scripts/build.py
```

输出位于 `dist/`，并附 SHA-256 校验文件。

`scripts/probe.cjs` 只验证本机 Codex 的初始化、账户是否可用、模型目录和历史读取。它不读取凭证文件，不打印邮件、token 或对话，不发起模型生成。

`scripts/prepare-smoke.py` 和 `tests/zotero-smoke.js` 用于独立测试配置，测试脚本不会打包进发布版。它们使用生成的示例 PDF，验证实际 Zotero 加载、正文提取、选文注释、Markdown/公式、推理档位、项目记忆和本机 Codex 通信。
